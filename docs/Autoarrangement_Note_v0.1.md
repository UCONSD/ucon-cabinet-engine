# Автоматическая расстановка кабинетов в ряд — проектная заметка

Документация обсуждения: как работает авторасстановка напольных модулей и
как она должна быть реализована в плагине UCON Cabinet. Черновик архитектуры,
не финальная спецификация.

---

## 1. Что это такое

Автоматическая расстановка в ряд (auto-placement / snapping) — постановка
модулей встык вдоль стены без ручного выравнивания каждого. Новый шкаф
прилипает боком к предыдущему: без зазора, на одной линии, на одном уровне
пола/цоколя. Результат — непрерывный ряд напольных модулей, как реальная
кухня вдоль стены.

---

## 2. Как работает механически

Три составляющие:

**Точка привязки.** У каждого шкафа определён «правый край» в его собственных
координатах (по модели плагина это X = ширина корпуса). Новый шкаф берёт
правый край предыдущего как стартовую точку X. Левый бок нового совпадает с
правым боком предыдущего.

**Выравнивание по осям.** Новый шкаф наследует Y (позицию по глубине) и Z
(уровень пола/цоколя) от ряда — чтобы фронты стояли в одну линию и всё было
на одной высоте. Меняется только X (сдвиг вдоль стены).

**Накопление смещения.** Плагин помнит суммарную ширину уже поставленных
модулей. Каждый следующий = предыдущее смещение + ширина нового. Ряд
600 + 900 + 600 занимает по X ровно 2100, модули стык в стык.

---

## 3. Два способа задания ряда

**Пакетный (приоритет).** Задаёшь в диалоге список модулей (артикулы +
количество) и стартовую точку — плагин строит весь ряд разом. Проще,
надёжнее, и под задачу «чертежи из каталога» подходит лучше: состав кухни
известен заранее из спецификации.

**Интерактивный (позже).** Кликаешь точку старта, ведёшь мышью, модули
раскладываются вдоль линии в реальном времени с прилипанием к сетке.
Реализуется через SketchUp Tool API (`Tool`-класс с `onMouseMove` /
`onLButtonDown`). Дороже в реализации, для чертежей не критично.

Решение: **оба со временем, начинать с пакетного.**

---

## 4. Нюансы, отличающие хорошую расстановку от кривой

- **Общий цоколь.** В реальной кухне цоколь — единая планка на весь ряд, а не
  по 100 мм под каждым шкафом. Хорошая расстановка либо бесшовно стыкует
  цоколи, либо генерит один общий на всю длину ряда.
- **Столешница.** Часто кладётся одной плитой поверх всего ряда, а не по
  отдельным шкафам.
- **Угловые модули.** Ряд вдоль двух стен требует поворота на 90° в углу —
  отдельная логика, не просто сдвиг по X (см. раздел 6).

---

## 5. Порядок разработки (от простого к сложному)

1. **Прямой ряд** — тривиально. Накопление ширины по X, стык в стык.
   Фундамент для всего остального.
2. **Угол** — качественно сложнее (см. раздел 6). Строится только после
   отлаженного прямого ряда.
3. **Интерактивное перетаскивание** — в последнюю очередь, когда геометрия
   отлажена.

Прыгать сразу в Г-образную на неготовом фундаменте — дольше и багованее.

---

## 6. Г-образная раскладка (две стены, угол)

Целевая раскладка для UCON — Г-образная. Угол — это НЕ «ряд + ещё ряд».

**Проблема угла.** Два ряда, сходящиеся в углу, физически конфликтуют: если
оба шкафа встанут вплотную к внутреннему углу, они займут одно место —
наложатся глубинами.

**Решение — угловой модуль как «шарнир».** В точке угла ставится специальный
угловой модуль (не заглушка и не простой нахлёст). Его размеры и тип задают,
как стыкуются ряды. Логика Г-образной:

1. Ряд A строится вдоль стены 1 (накопление по X).
2. В точке угла ставится угловой модуль. Он занимает квадрат в углу; его
   геометрия определяет стык.
3. Ряд B продолжается от углового модуля, повёрнутый на 90° вдоль стены 2.

Угловой модуль — шарнир, геометрия которого задана его каталожной записью,
а не логикой плагина.

**Ключевое решение: угловой модуль выбирается из каталога**, а не зашит одной
стратегией. В каталоге фабрики угловые — это конкретные артикулы со своими
размерами (как обычные base-модули). Плагин берёт выбранный артикул, знает
его размеры и тип «corner», и стыкует по нему ряды.

---

## 7. Зависимость от каталога модулей (фундамент)

Расстановка не имеет смысла без источника данных о модулях. Поэтому раньше
расстановки идёт **каталог модулей как данные, отдельно от кода**.

Принцип: данные отдельно от логики. Каталог — источник истины, плагин —
исполнитель. Каталог пополняется из PDF фабрики без правки движка.

Каждая запись модуля хранит как минимум:

| Поле        | Пример    | Назначение                              |
| ----------- | --------- | --------------------------------------- |
| Артикул     | UI0658    | идентификатор                           |
| Тип         | base      | base / corner / filler                  |
| Ширина      | 600 мм    | X, участвует в накоплении               |
| Высота корп.| 780 мм    | Z корпуса (без цоколя)                  |
| Глубина     | 620 мм    | Y корпуса (без фасада)                  |
| Особенность | 1 дверь   | двери/полки/угловой/заглушка            |

Правильная последовательность работ:

1. **Каталог модулей** — вынести размеры из кода в структуру данных
   (несколько base + угловой + filler). Диалог строит любой модуль по выбору
   артикула.
2. **Прямой ряд** — расстановка списком из каталога, накопление, общий цоколь.
3. **Г-образная** — угловой модуль из каталога как шарнир + поворот ряда B.

---

## 8. Открытые вопросы (на решение)

- Формат хранения каталога: `catalog.rb` (Ruby-структура) или `catalog.json`
  (данные, легче пополнять и парсить из PDF).
- Общий цоколь: генерить одной планкой на весь ряд или стыковать по модулям.
- Столешница: включать ли в расстановку сразу или отдельным шагом.
- Как именно угловой модуль стыкует ряды по своим граням (зависит от типа
  углового: диагональный, L-образный, с каруселью).
- Наследование Y при повороте ряда B на 90° в углу.

---

## Связь с общей целью

Финальная цель плагина — не производственная спецификация, а презентационные
CAD-чертежи в LayOut (проволочный стиль, 4 вида: фронт / план / бок /
изометрия). Расстановка нужна, чтобы собрать кухню из каталожных модулей и
получить с неё чертёж. Приоритет — данные на выходе и корректная геометрия
ряда, а не богатство 3D-детализации.
