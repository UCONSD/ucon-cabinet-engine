**1. Project objective**
Build a controlled, source-based technical planning system that allows
UCON to:

1.  prepare preliminary Cesar kitchen layouts in SketchUp;

2.  organize cabinet, appliance, filler, panel, plinth, and grip-recess
    requirements;

3.  create structured quote-request packages for Cesar / DzineElements
    review;

4.  evaluate the operational feasibility of a Cesar dealership or
    cabinet-supply workflow;

5.  reduce unsupported assumptions before pricing, quotation, or order
    preparation.
    The current system is for **preliminary planning only**. It is not a
    production-order system, final pricing system, or confirmation of
    current product availability.

    **10. Rules for future extraction**
    10.1 Original PDF first
    Every technical rule, module, dimension, code, restriction, or
    commercial term must begin with the original manufacturer PDF.
    The original PDF remains the controlling source when an internal
    extract is incomplete, ambiguous, or inconsistent.
    **10.2 Markdown extract first**
    New extraction work must first be written as a controlled Markdown
    document or table that preserves:

-   source filename;

-   page or section;

-   manufacturer terminology;

-   dimensions;

-   restrictions;

-   unresolved questions;

-   status;

-   assumptions.
    **10.3 Review before Excel**
    No extracted data should be transferred into Excel until the
    Markdown extract has been checked against the source PDF.
    Review must identify:

<!-- -->

-   transcription errors;

-   collection mixing;

-   missing restrictions;

-   nominal versus finished dimensions;

-   unclear item-code readings;

-   unsupported assumptions;

-   Elda confirmation requirements.
    **10.4 Excel only for operational tables**
    Excel should be used for:

<!-- -->

-   component schedules;

-   module tables;

-   dropdowns;

-   confirmation gates;

-   quote-request schedules;

-   status tracking;

-   comparison matrices.
    Excel should not become the primary narrative interpretation of the
    Cesar system.
    **10.5 No final pricing**
    Do not create final client pricing without confirmed:

<!-- -->

-   current manufacturer pricing or point structure;

-   dealer coefficient or discount;

-   freight;

-   tariffs and import costs;

-   sales tax treatment;

-   margin requirement;

-   installation scope;

-   responsibility split;

-   current commercial terms.
    **10.6 No production order authority**
    No Markdown guide, Excel table, SketchUp model, or AI-generated
    layout is production-order authority.
    A production order requires Cesar / DzineElements technical review
    and all manufacturer-required order information, including confirmed
    codes, exact measurements, drawings, finishes, and commercial
    approval.
    **10.7 Elda confirmation required**
    Elda / DzineElements confirmation is required before a generic
    planning block becomes a quote-request or order-related module,
    including confirmation of:

<!-- -->

-   collection;

-   door family;

-   opening system;

-   base-height system;

-   plinth height and finish;

-   appliance models;

-   USA Elements compatibility;

-   production availability;

-   filler requirements;

-   end-panel construction;

-   tall-unit height and front alignment;

-   current commercial applicability.

    **11. Stop conditions / risks**
    Stop extraction or prevent downstream use when any of the following
    occurs:

1.  **Collection is not confirmed.**
Do not combine module schedules
    from different collections into one operational library.

2.  **Exact appliance models are missing.**
Do not convert nominal
    appliance widths into final cabinet or panel geometry.

3.  **Source page is unclear or illegible.**
Mark the item as
    unresolved. Do not invent a code, dimension, or restriction.

4.  **Current availability is unconfirmed.**
Catalog presence must not
    be represented as current production availability.

5.  **An internal extract conflicts with the original PDF.**
Stop and
    resolve the discrepancy from the PDF before updating Excel or
    SketchUp.

6.  **A proposed Excel table has no reviewed Markdown source.**
Do not
    approve it for operational use.

7.  **Bobby-specific room or appliance information remains
    missing.**
The catalog system may continue to be extracted, but the
    project layout must remain unvalidated.

8.  **Pricing inputs are incomplete.**
Do not create final client
    pricing or dealership economics.

9.  **The model is being treated as production-ready.**
Reclassify it as
    preliminary and require Cesar / DzineElements technical review.

10. **Extraction scope expands toward full-catalog digitization.**
Stop
    and return to the pilot-required module list. Full-catalog
    extraction increases complexity without resolving the immediate
    project constraint.

11. **Duplicate files contain different content.**
Stop using both
    versions until one canonical source is selected and the source
    register is updated.

12. **Elda confirmation is unavailable for a decision-critical
    item.**
Keep the item in `NEEDS_ELDA_CONFIRMATION` status and
    prevent it from advancing to quote-request or order use.
