- Do not use final Cesar item codes in component names.
- A workbook row does not override the cited manufacturer PDF.
- `Build now` means a preliminary non-production object may enter `90_Review_Pending`; it does not mean confirmed availability.

## QC Checklist

| QC Gate | Check | Pass criteria | Record required |
|---|---|---|---|
| Gate 1 — Source Review | Source identity and page | Source workbook/file, sheet/section, source PDF, printed page, and PDF page are recorded or marked not applicable. | Reviewer, date, source basis |
| Gate 1 — Source Review | Eligibility | Row is P1/use or explicitly permitted as a controlled project-only planning object. | Build status and priority |
| Gate 1 — Source Review | Restrictions | All cautions, Elda gates, and unresolved dimensions are retained. | Assumption / caution note |
| Gate 2 — Build Review | Units and axes | Millimeters, consistent origin/insertion point, correct axes, and valid bounding box. | Build reviewer and date |
| Gate 2 — Build Review | Separation | Carcass, opening/front, filler, panel, plinth, grip, worktop, appliance, and clearance objects remain separate. | Component test record |
| Gate 2 — Build Review | Geometry level | No hardware, joinery, machining, detailed mechanisms, cutouts, wiring, or decorative heavy geometry. | LOD check |
| Gate 2 — Build Review | Parameters | Adjustable fields work without creating unsupported combinations; restricted values are visible. | Parameter test |
| Gate 2 — Build Review | Metadata | Required metadata fields are complete; unknowns use `TBD`, not invented values. | Metadata audit |
| Gate 2 — Build Review | Performance | Low polygon count, no unnecessary textures, no hidden heavy geometry, file purged. | File-size/performance check |
| Gate 3 — Model Test | Placement and alignment | Insertion, resizing, replacement, run alignment, and bounding behavior are reliable. | Pilot test result |
| Gate 3 — Model Test | Interface testing | Panel/filler separation, plinth continuity, grip alignment, appliance envelope fit, and clearance visibility are tested. | Conflict log |
| Gate 3 — Model Test | Schedule/export readability | Names, metadata, statuses, and assumptions remain readable in schedules/exports. | Export check |
| Gate 4 — Release | Owner approval | Library owner approves movement from `90_Review_Pending`; builder does not self-release. | Release record and version |
| Gate 4 — Release | Change control | Revision, reason, source, reviewer, affected files, and backward-compatibility impact are logged. | Change log |

## Release Gate

A Phase 1 component is releasable only when its source basis, geometry, metadata, model test, and owner approval are complete. `NEEDS_ELDA_CONFIRMATION` may remain as a visible status for a generic preliminary placeholder, but no asset may be represented as a confirmed Cesar module until the linked confirmation is received and recorded.
